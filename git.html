Setup

Configure Git once per computer; --global settings apply to every repository. Then start a new repository or copy an existing one.

git config --global user.name "Ana Diaz"The name on your commits
git config --global user.email "ana@example.com"
git config --global init.defaultBranch mainName the first branch of new repos main
git config --global pull.rebase truePull rebases your work instead of merging
git config --global core.editor "code --wait"Editor for commit messages (VS Code here)
git config --global alias.lg "log --oneline --graph --all"Then git lg runs that
git config --list --show-originEvery setting, and the file it comes from
git initStart a repository in the current folder
git clone <url> [<folder>]Copy a repository and its history

Everyday workflow

Changes move from your files to the staging area to a commit. Staging lets you choose exactly what goes into each commit.

git statusWhat changed, and what's staged
git add <file>Stage a file for the next commit
git add .Stage everything in this folder and below
git add -pChoose changes hunk by hunk
git commit -m "Add size chart"Commit what's staged
git commit -am "Fix typo"Stage changed tracked files and commit (skips new files)
git diffChanges you haven't staged
git diff --stagedStaged changes: what the commit will contain
git log --oneline --graphCompact history with branch lines

Branches

A branch is a movable pointer to a commit, so creating one is instant. Work on a branch, then merge it back when it's ready.

git branchLocal branches; * marks the current one
git branch -aInclude remote-tracking branches
git switch -c <branch>Create a branch and switch to it
git switch <branch>Switch to an existing branch
git switch -Back to the previous branch
git merge <branch>Merge it into the current branch
git merge --no-ff <branch>Always record a merge commit
git branch -m <new-name>Rename the current branch
git branch -d <branch>Delete a merged branch (-D deletes it anyway)

Remotes

A remote is another copy of the repository, usually on GitHub, named origin by default. Fetch downloads new commits; pull also brings them into your branch.

git remote -vRemotes and their URLs
git remote add origin <url>Connect a remote named origin
git fetchDownload new commits without touching your files
git pullFetch, then merge or rebase into the current branch
git push -u origin <branch>First push; -u remembers where to push next time
git pushPush to the branch's upstream
git push --force-with-leaseForce push, but refuse if the remote changed since you fetched
git push origin --delete <branch>Delete a branch on the remote
git branch -vvEach branch's upstream, and how far ahead or behind it is

Undoing changes

Pick the command by how far the change has gone: still in your files, staged, committed, or already pushed. reset and --amend rewrite commits, so use revert for anything others have pulled.

git restore <file>Discard unstaged changes to a file
git restore --staged <file>Unstage it, keeping the changes
git commit --amendRedo the last commit with what's staged and a new message
git reset --soft HEAD~1Undo the last commit; its changes stay staged
git reset HEAD~1Undo the last commit; its changes stay unstaged
git reset --hard HEAD~1Undo the last commit and throw away its changes and any uncommitted work
git revert <commit>A new commit that reverses an old one; safe on shared branches
git clean -nPreview deleting untracked files (-f deletes them, -d includes folders)
git reflogEverywhere HEAD has been; finds commits you thought were lost

Stash

The stash shelves uncommitted changes so you can switch tasks with a clean working folder, then bring them back later.

git stashShelve tracked changes
git stash -uInclude untracked files
git stash push -m "wip: cart" <file>Shelve only some files, with a message
git stash listStashes, newest first as stash@{0}
git stash popReapply the latest and remove it from the list
git stash apply stash@{1}Reapply one and keep it in the list
git stash drop stash@{1}Delete one
git stash branch <branch>Make a branch from the stash and apply it there

Viewing history

Git keeps every commit, so you can see what changed, who changed it, and when. Filters narrow a long history down to the commits you care about.

git logCommits, newest first
git log --oneline -n 10The last 10, one line each
git log -p <file>Every change to one file
git log --author="Ana" --since="2 weeks ago"Filter by author and date
git log --grep="cart"Search commit messages
git log -S "applyDiscount"Commits that added or removed this text
git show <commit>One commit's message and changes
git blame <file>Who last changed each line
git shortlog -snCommit counts per author

Rebase & rewriting history

Rebasing replays commits on a new base for a straight history, and interactive rebase lets you edit, combine or drop commits. Rewritten commits get new IDs, so only rewrite commits you haven't shared.

git rebase mainReplay this branch's commits on top of main
git rebase -i HEAD~3Edit the last 3: pick, reword, squash, fixup or drop each one
git rebase --continueAfter resolving a conflict (--abort cancels)
git commit --fixup <commit>A commit marked to be folded into an earlier one
git rebase -i --autosquash mainFold fixup commits into their targets
git cherry-pick <commit>Copy one commit onto the current branch
git history reword <commit>Change an old commit's message (experimental, Git 2.54+)
git history split <commit>Split a commit in two (experimental, Git 2.54+)
git history fixup <commit>Fold staged changes into an old commit (experimental, Git 2.55+)

Merge conflicts

A conflict happens when both sides changed the same lines. Git marks both versions in the file; edit it to the result you want, remove the markers, and stage it. During a rebase, --ours and --theirs are swapped.

<<<<<<< HEADYour branch's version
price: 20
=======
price: 25
>>>>>>> feature/pricingThe incoming version
git statusLists the conflicted files
git add <file>Mark it resolved after editing
git commitFinish the merge (git rebase --continue during a rebase)
git merge --abortGive up and go back to before the merge
git restore --ours <file>Keep your whole version of the file (--theirs keeps theirs)

Tags

Tags name a specific commit, usually a release. Annotated tags store who made them, when and why; lightweight tags are just a name.

git tagList tags
git tag v1.2.0A lightweight tag on the current commit
git tag -a v1.2.0 -m "Fall release"Annotated: author, date and message
git push origin v1.2.0Tags aren't pushed unless you ask
git push --tagsPush every tag
git tag -d v1.2.0Delete it locally (git push origin --delete v1.2.0 for the remote)
git describe --tagsNearest tag, like v1.2.0-3-gabc1234: 3 commits after it

.gitignore

A .gitignore file lists files Git shouldn't track, like dependencies, build output and secrets. It only affects untracked files; anything already committed stays tracked.

node_modules/A folder with this name, anywhere
*.logEvery file ending in .log
!keep.logExcept this one
/buildOnly build at the repository root
**/tempTemp at any depth
.envSecrets and local settings
git rm --cached <file>Stop tracking a file that's now ignored; it stays on disk
git check-ignore -v <file>Which rule ignores it

Refs & ranges

Most commands take a commit, and there are many ways to name one. Ranges select sets of commits for log, diff and other commands.

WriteTo mean
HEADThe commit you have checked out
HEAD~2Two commits before HEAD
HEAD^2The second parent of a merge commit
abc1234A commit by the start of its hash
origin/mainWhere main was on the remote at your last fetch
@{u}The current branch's upstream
main..featureCommits on feature that aren't on main
main...featureIn log: commits on either side but not both. In diff: what feature changed since they split

Finding bugs & multitasking

git bisect finds the commit that introduced a bug by binary search, and worktrees let you check out a second branch in another folder without stashing.

git bisect startStart a binary search through history
git bisect badThe current commit has the bug
git bisect good v1.2.0This one didn't; Git checks out one halfway between
git bisect resetFinish and go back to where you started
git worktree add -b hotfix ../hotfix mainA second folder on a new branch from main
git worktree list
git worktree remove ../hotfix
git grep "applyDiscount"Search the tracked files
