Document structure

Every page has the same skeleton. The head holds information about the page, like its title and the files it loads, and the body holds everything visible.

<!DOCTYPE html>Standards mode; always the first line
<html lang="en">Page language, for screen readers and translation
<head>
<meta charset="utf-8">Character encoding; keep it first in the head
<meta name="viewport" content="width=device-width, initial-scale=1">Fit the screen on phones
<title>Page title</title>Shown in the browser tab and in search results
<link rel="stylesheet" href="style.css">
<script src="app.js" defer></script>Run after the page has been parsed
</head>
<body>
<h1>Hello</h1>Everything visible goes in the body
</body>
</html>

Text

Choose elements for what the text means, not how it should look; CSS handles the look. Browsers, search engines and screen readers all rely on that meaning.

<h1>Title</h1> <h2>Section</h2>Headings h1 to h6: one h1, and don't skip levels
<p>A paragraph.</p>
<strong>Important</strong>Strong importance (bold by default)
<em>Stressed</em>Stress emphasis (italic by default)
<mark>Highlighted</mark>Marked as relevant, like search matches
<small>Fine print</small>Side comments and legal text
<code>let x = 1;</code>Inline code
<pre>Keeps its spacing</pre>Preformatted: whitespace stays as written
<blockquote cite="https://example.com">A long quote.</blockquote>
<q>A short quote</q>Adds quotation marks
<abbr title="HyperText Markup Language">HTML</abbr>Abbreviation, with the expansion on hover
<time datetime="2026-10-01">October 1</time>A date machines can read
H<sub>2</sub>O and x<sup>2</sup>Subscript and superscript
<kbd>Ctrl</kbd> + <kbd>C</kbd>Keyboard input
Line one<br>Line twoLine break, for addresses and poems
<hr>A thematic break between topics

Links

The a element links to another page, a place on the same page, a file, or an email address or phone number. Link text should make sense on its own, so avoid "click here".

<a href="https://example.com">Example</a>Another site
<a href="/about">About us</a>A page on the same site
<a href="#faq">FAQ</a>Jump to the element with id="faq"
<a href="https://example.com" target="_blank">Docs</a>Open in a new tab (implies rel="noopener")
<a href="mailto:hi@example.com">Email us</a>Open the mail app
<a href="tel:+15551234567">Call us</a>Call on phones
<a href="report.pdf" download>Report</a>Save instead of opening (same-origin files only)
<nav aria-label="Main">A block of major navigation links
<a href="/">Home</a> <a href="/blog">Blog</a>
</nav>

Images & media

Images need alt text that says what the image shows, or an empty alt if it's decorative. Giving width and height lets the browser reserve the space before the file loads.

<img src="cat.jpg" alt="A cat asleep on a sofa" width="800" height="600">Alt text is read aloud; width and height prevent layout shift
<img src="divider.svg" alt="">Empty alt: decorative, so screen readers skip it
<img src="map.png" alt="Store map" loading="lazy">Load only when it's about to scroll into view
<img src="photo-800.jpg" alt="Harbor at dusk"
srcset="photo-400.jpg 400w, photo-800.jpg 800w"
sizes="(max-width: 600px) 100vw, 50vw">The browser picks the best file for the screen
<picture>Offer other formats or crops
<source srcset="photo.avif" type="image/avif">
<img src="photo.jpg" alt="Harbor at dusk">The fallback, and where alt goes
</picture>
<figure>Content with a caption
<img src="chart.png" alt="Sales rose 20% in Q3">
<figcaption>Quarterly sales</figcaption>
</figure>
<video src="clip.mp4" controls muted playsinline poster="still.jpg"></video>The controls attribute shows the player's buttons
<audio src="talk.mp3" controls></audio>
<iframe src="https://example.com/embed" title="Store map" loading="lazy"></iframe>Embed another page; title names it

Lists & tables

Lists group related items, and tables are for data with rows and columns, not for page layout. Header cells and a caption make a table understandable without seeing it.

<ul><li>Apples</li><li>Pears</li></ul>Unordered list (bullets)
<ol><li>Mix</li><li>Bake</li></ol>Ordered list; start="5" and reversed change the numbers
<dl>Description list: terms and their descriptions
<dt>HTML</dt><dd>Structure</dd>
<dt>CSS</dt><dd>Presentation</dd>
</dl>
<table>
<caption>Opening hours</caption>The table's title
<thead>
<tr><th scope="col">Day</th><th scope="col">Hours</th></tr>Header cells; scope says which way they apply
</thead>
<tbody>
<tr><th scope="row">Mon</th><td>9–5</td></tr>
<tr><td colspan="2">Closed on holidays</td></tr>A cell that spans two columns
</tbody>
</table>

Forms

A form collects input and sends it as name and value pairs. Every field needs a label, which also makes it easier to tap, and the browser can check many rules before the form is sent.

<form action="/signup" method="post">Where and how to send it (method is get by default)
<label for="email">Email</label>The for value matches the input's id
<input id="email" name="email" type="email" required autocomplete="email">The name is the key in the sent data
<label><input type="checkbox" name="terms" required> I agree</label>Wrapping links them too
<select name="size">Dropdown
<option value="s">Small</option>
<option value="m" selected>Medium</option>
</select>
<textarea name="note" rows="4" maxlength="500"></textarea>Multi-line text
<fieldset>A group of related fields
<legend>Plan</legend>
<label><input type="radio" name="plan" value="free" checked> Free</label>Same name: only one can be picked
<label><input type="radio" name="plan" value="pro"> Pro</label>
</fieldset>
<button type="submit">Sign up</button>A button's type is submit unless you say otherwise
<button type="reset">Clear</button>Restore the starting values
</form>

Input types

The type attribute changes the control the browser shows, which keyboard phones open, and what gets checked before the form is sent.

TypeWhat you get
type="text"Single-line text (the default)
type="email"Checks for an email address; email keyboard on phones
type="password"Hides the characters as they're typed
type="number"Numbers only, with step buttons
type="tel"Phone keyboard; the format isn't checked
type="url"Checks for a full URL
type="search"Text field styled for search, often with a clear button
type="date"Date picker (also time, datetime-local, month, week)
type="range"Slider between min and max
type="color"Color picker; the value is a hex color
type="checkbox"On or off; only sent when checked
type="radio"Pick one from the group with the same name
type="file"File chooser; add multiple and accept="image/*"
type="hidden"Sent with the form but not shown

Validation & input attributes

Built-in validation blocks the submit and shows a message until the rules pass. It improves the experience, but always check the data again on the server.

AttributeWhat it does
requiredMust be filled in before the form can be sent
minlength="8" maxlength="64"Allowed length of the text
min="1" max="10" step="1"Allowed range for numbers and dates
pattern="[0-9]{5}"The whole value must match this regular expression
placeholder="you@site.com"Example shown while empty; not a replacement for a label
autocomplete="email"Lets the browser offer saved values
inputmode="numeric"Which on-screen keyboard to show
readonlyCan't be changed, but is still sent
disabledCan't be used and isn't sent
novalidateOn the form: skip the built-in checks

Page layout

These elements describe the regions of a page. Screen readers list them as landmarks users can jump between, which plain divs can't do.

<header>Logo and search</header>Introduction for the page or a section
<nav>…</nav>Major navigation links
<main>The page's main content; one per page
<article>Self-contained: a post, a product, a comment
<h2>Post title</h2>
<section>…</section>A thematic group, usually with a heading
</article>
<aside>Related posts</aside>Related but separate, like a sidebar
</main>
<footer>&copy; 2026</footer>Closing content: copyright, contact, links
<address>hi@example.com</address>Contact details for the page or article
<search><form>…</form></search>Wraps a search or filter form
<div>…</div> <span>…</span>No meaning; use them when nothing else fits

Interactive elements

Some interactive UI is built into HTML: disclosure widgets, dialogs and popovers come with keyboard support and accessibility, often without any JavaScript.

<details>Opens and closes, no JavaScript needed
<summary>Shipping</summary>Always visible; click it to toggle
<p>Ships in 2 days.</p>
</details>
<details name="faq"><summary>Returns</summary>…</details>Same name: opening one closes the others
<dialog id="confirm">A dialog box
<form method="dialog">Submitting this form closes the dialog
<button value="ok">OK</button>
</form>
</dialog>
<button commandfor="confirm" command="show-modal">Delete…</button>Open the dialog as a modal, no JavaScript
<button popovertarget="menu">Menu</button>Shows and hides the popover
<div id="menu" popover>…</div>On top of everything; closes on outside click or Esc
<progress value="70" max="100">70%</progress>Progress of a task
<meter value="0.6">60%</meter>A measurement within a known range

Global attributes

These attributes work on any element. id and class are the hooks CSS and JavaScript use most.

AttributeWhat it does
id="intro"Unique name for links, labels, CSS and scripts
class="card wide"Space-separated names for CSS and scripts
style="color: red"Inline CSS; a stylesheet is easier to maintain

lang="fr"Language of this part of the page
dir="rtl"Text direction

Accessibility

Native elements already work with keyboards and screen readers, so reach for them first. ARIA attributes fill gaps when there's no visible text or no native element for the job.

<button type="button">Save</button>✓ Focusable and works with Enter and Space
<div class="btn">Save</div>✗ Can't be focused or used from the keyboard
<button aria-label="Close">&times;</button>A name for screen readers when there's no visible text
<input type="password" name="pw" aria-describedby="pw-hint">Links extra help text
<p id="pw-hint">At least 8 characters.</p>
<nav aria-labelledby="toc-title">…</nav>Names the region using visible text elsewhere
<svg aria-hidden="true">…</svg>Hides a decorative graphic from screen readers
<p aria-live="polite">3 results</p>Screen readers announce changes
<a href="#main">Skip to content</a>An early link that lets keyboard users skip the menu
<div role="alert">Payment failed</div>Role adds meaning, but prefer a native element

Head & metadata

Metadata isn't shown on the page but tells browsers, search engines and social sites about it, and controls how and when scripts and other files load.

<meta name="description" content="Short summary">The snippet search engines may show
<link rel="icon" href="/favicon.svg" type="image/svg+xml">
<link rel="canonical" href="https://example.com/page">The preferred URL when there are copies
<meta property="og:title" content="Page title">Title for link previews (Open Graph)
<meta property="og:image" content="https://example.com/card.png">
<meta name="theme-color" content="#1c1c1c">Color for the browser's UI on some phones
<meta name="color-scheme" content="light dark">The page supports both themes
<link rel="preconnect" href="https://fonts.gstatic.com">Open a connection early
<link rel="preload" href="hero.avif" as="image">Start loading an important file early
<script src="a.js" async></script>Runs as soon as it loads, in any order
<script src="b.js" defer></script>Runs in order, after the page is parsed
<script type="module" src="app.js"></script>JavaScript module; deferred by default
<noscript>Please turn on JavaScript.</noscript>Shown only when scripts are off

Character references

With UTF-8 you can type almost any character directly. You only need these for characters HTML would otherwise read as markup, or ones that are hard to type.

WriteTo get
