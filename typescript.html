Basic types

TypeScript checks your code against types before it runs, then removes them, so the JavaScript you ship is unchanged. Annotate where it helps and let TypeScript infer the rest.

let city: string = "Lima";Annotate with : Type
let age = 30;Inferred as number
let ok: boolean = true;
let big: bigint = 10n;
let ids: number[] = [1, 2];Array, same as Array<number>
let pair: [string, number] = ["a", 1];Tuple: fixed length and types
let dir: "up" | "down" = "up";Literal type: only these values
let maybe: string | null = null;Null has to be allowed explicitly (strict mode)
let a: any;Turns type checking off for this value
let u: unknown;Any value, but you must narrow it before use
let o: object = {};Any non-primitive value
function log(msg: string): void { }Returns nothing useful
function fail(): never {Never returns (throws or loops forever)
throw new Error("fail");
}

Object types & interfaces

Object types describe the shape of a value: which properties it has and the type of each. type and interface both do this; interfaces can be extended and reopened, while type can also name unions and other non-object types.

type Point = { x: number; y: number };Type alias for an object shape
interface User {Interface: an object shape you can extend
readonly id: number;Can't be reassigned after creation
name: string;
email?: string;Optional: string | undefined
}
interface Admin extends User {Inherits all of User's members
role: "admin";
}
type Staff = User & { team: string };Intersection: has both sets of members
interface User { age?: number }Interfaces with the same name merge
type Scores = { [name: string]: number };Index signature: any string key
const p: Point = { x: 1, y: 2 };
const u: User = { id: 1, name: "Ana" };Optional members can be left out

Unions & narrowing

A union says a value can be one of several types. Check which one you have before using type-specific features, and TypeScript narrows the type inside that branch.

type Id = string | number;Union: one of several types
function show(id: Id) {
if (typeof id === "string") {
id.toUpperCase();Narrowed to string here
} else {
id.toFixed(2);Narrowed to number here
}
}
if ("email" in user) { … }Narrow by checking for a property
if (err instanceof Error) { … }Narrow by class
type Shape =Discriminated union: members share a literal key
| { kind: "circle"; r: number }
| { kind: "square"; size: number };
function area(s: Shape): number {
switch (s.kind) {Checking kind narrows s
case "circle": return Math.PI * s.r ** 2;
case "square": return s.size ** 2;
default: return s satisfies never;Compile error here if a case is missing
}
}
function isStr(x: unknown): x is string {Type guard: narrows x wherever it's called
return typeof x === "string";
}

Assertions & checks

These tell the compiler something it can't work out on its own. !, as and !: are promises, not checks, and do nothing at runtime, so a wrong one hides a bug. satisfies and as const are the safe ones.

const app = document.getElementById("app")!;!: assert it isn't null or undefined
const input = app as HTMLInputElement;As: treat it as a more specific type
const conf = { port: 80 } satisfies Record<string, number>;Check against a type, keep the inferred one
const dirs = ["up", "down"] as const;As const: readonly ["up", "down"]
let total!: number;Definite assignment: trust it's set before use

Generics

Type parameters like T are placeholders that get filled in each time a function, interface or class is used. One piece of code then works with many types while keeping input and output types linked.

function first<T>(arr: T[]): T | undefined {T is filled in at each call
return arr[0];
}
first([1, 2]);T inferred as number
first<string>(["a"]);Or passed explicitly
function longest<T extends { length: number }>(a: T, b: T) {Constraint: T must have length
return a.length >= b.length ? a : b;
}
function get<T, K extends keyof T>(o: T, k: K): T[K] {K must be a key of T
return o[k];
}
interface Box<T = string> { value: T }Default type argument
class Stack<T> {Generic class
private items: T[] = [];
push(x: T) { this.items.push(x); }
pop(): T | undefined { return this.items.pop(); }
}

Classes

JavaScript classes plus type annotations and access modifiers. private, protected and readonly are only enforced by the compiler; # fields stay private at runtime too.

static count = 0;Belongs to the class itself

#pin = 1234;JS private field (enforced at runtime too)
protected owner: string;This class and its subclasses

this.id = id;
this.owner = owner;
}
}

Enums & constants

An enum is a named set of constants, and unlike most TypeScript features it creates a real object at runtime. Many projects use an as const object instead, which is plain JavaScript.

enum Dir { Up, Down }Numeric: Up = 0, Down = 1
enum Level { Low = "low", High = "high" }String enum
Dir.Up;0
Dir[0];"Up" (numeric enums map back to names)
const enum Flag { A = 1, B = 2 }Inlined at compile time, no object emitted
const Color = { Red: "red", Blue: "blue" } as const;Plain-object alternative to an enum
type Color = (typeof Color)[keyof typeof Color];"red" | "blue"

Utility types

Built-in generic types that transform other types, so you can derive new types from existing ones instead of writing them out again.

TypeWhat it gives you
Partial<T>Every property optional
Required<T>Every property required
Readonly<T>Every property read-only
Pick<T, "a" | "b">Only the listed properties
Omit<T, "a">Every property except the listed ones
Record<K, V>Object type with keys of type K and values of type V
Exclude<U, X>Members of union U that aren't assignable to X
Extract<U, X>Members of union U that are assignable to X
NonNullable<T>T without null and undefined
ReturnType<typeof fn>A function's return type
Parameters<typeof fn>A function's parameter types, as a tuple
Awaited<T>What a Promise resolves to, unwrapping nested promises
InstanceType<typeof C>The type of instances a class creates

Type operators

Types can be computed from other types and from values. These operators are the building blocks the utility types are made from.

interface User { id: number; name: string; email?: string }
type UserKey = keyof User;"id" | "name" | "email"
const config = { port: 80 };
type Config = typeof config;Type of a value: { port: number }
type Name = User["name"];Indexed access: string
const langs = ["ts", "js"] as const;
type Lang = (typeof langs)[number];Element type: "ts" | "js"
type IsStr<T> = T extends string ? true : false;Conditional type
type Elem<T> = T extends (infer U)[] ? U : T;Infer captures part of a type
type Opt<T> = { [K in keyof T]?: T[K] };Mapped type (how Partial works)
type Ev = `on${"Click" | "Key"}`;Template literal type: "onClick" | "onKey"
type Getters<T> = {Key remapping with as
[K in keyof T as `get${Capitalize<string & K>}`]: () => T[K];

Modules & declarations

Types are imported and exported like values but disappear from the compiled JavaScript. declare describes things that exist at runtime but aren't written in TypeScript, and .d.ts files hold only declarations.

main.ts

Async & errors

An async function always returns a Promise of its result type. JavaScript can throw any value, so in strict mode a caught error is unknown until you narrow it.

async function load(id: number): Promise<User> {Async functions return a Promise
const res = await fetch(`/api/users/${id}`);
if (!res.ok) throw new Error(`HTTP ${res.status}`);Fetch doesn't reject on 404 or 500
return (await res.json()) as User;The parsed JSON is typed any, so assert the shape
}
try {
await load(1);
} catch (err) {In strict mode, err is unknown
if (err instanceof Error) console.error(err.message);Narrow before using it
}
const both = await Promise.all([load(1), load(2)]);[User, User]
type Loaded = Awaited<ReturnType<typeof load>>;User

tsconfig & CLI

tsconfig.json tells the compiler which files to check and how strictly. tsc type-checks and compiles to JavaScript, though many projects only use it to type-check and let a bundler or Node run the code.

{
"compilerOptions": {
"target": "es2025",JS version to emit (the default in TS 7)
"module": "nodenext",For Node; bundlers use "esnext" with "moduleResolution": "bundler"
"strict": true,On by default since TS 6; explicit for older versions
"types": ["node"],@types packages to load (none by default since TS 6)
"noUncheckedIndexedAccess": true,Makes arr[i] T | undefined
"rootDir": "src",Where the sources are
"outDir": "dist"Where compiled JS goes
},
"include": ["src"]
}
npm install -D typescriptAdd the compiler to a project
