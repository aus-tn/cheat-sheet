Components & props

A component is a function that returns JSX, and its name must start with a capital letter. Props pass data from parent to child; they're read-only, so a component never changes its own props.

State

State is data a component remembers between renders. Calling the setter schedules a re-render with the new value, so treat state as read-only and replace objects and arrays instead of changing them.

Reducers & custom hooks

A reducer moves update logic out of the component: events dispatch actions, and one function decides the next state. Custom hooks package stateful logic so several components can reuse it.

case "removed": return state.filter(t => t.id !== action.id);
default: return state;
}
}

Rules & pitfalls

Hooks must run in the same order on every render, and state changes only show up when you pass React a new value. Most React bugs come from breaking one of these.

if (open) useState(0);✗ Hooks can't go in conditions, loops or after an early return
const [a, setA] = useState(0);✓ Call hooks at the top level of a component or hook
items.push(item); setItems(items);✗ Same array: React sees no change
setItems([...items, item]);✓ Pass a new array
<button onClick={save()}>Save</button>✗ Calls save while rendering
<button onClick={() => save()}>Save</button>✓ Passes a function to call on click
{count && <Badge />}✗ Renders 0 when count is 0
{count > 0 && <Badge />}✓ Keep the left side a boolean
<li key={index}>…</li>✗ Index keys mix up state when items move
<li key={item.id}>…</li>✓ Use a stable id
