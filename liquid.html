Liquid basics

Liquid is Shopify's template language: it runs on Shopify's servers and outputs the HTML each page sends. Double braces print a value, and brace-percent tags run logic.

{{ product.title }}Output: print a value
{{ product.title | upcase }}Filter: change a value before it's printed
{% if product.available %}In stock{% endif %}Tag: logic and control flow
{%- assign x = 1 -%}Hyphens strip the whitespace around the tag
{% # an inline comment %}
{% comment %}A longer comment{% endcomment %}
{% raw %}{{ not run }}{% endraw %}Print Liquid syntax without running it
{% liquidSeveral tags in one block, one per line
assign sale = product.compare_at_price
if sale
echo 'On sale'
endif
%}

Variables & types

Variables hold strings, numbers, booleans, nil, arrays and objects. Every value counts as true in a condition except nil and false, so an empty string is still true.

{% assign name = 'Ana' %}Create or replace a variable
{% assign count = 3 %}
{% assign on_sale = true %}
{% assign colors = 'red,blue' | split: ',' %}Arrays come from objects or split
{% capture greeting %}Hi, {{ name }}!{% endcapture %}Save rendered output as a string
{{ product.title }} {{ product['title'] }}Dot or bracket access
{{ product.images[0] }} {{ product.images.first }}By index, or first, last and size
{% if product.description == blank %}…{% endif %}Blank: nil, false or empty
{% if cart.items == empty %}…{% endif %}Empty: an empty string, array or object

Conditions

Conditions compare values with ==, !=, <, >, <=, >= and contains, and combine them with and or or. There are no parentheses, and several and/or operators are checked from right to left.

Loops

for repeats over an array or a range. Inside a loop, the forloop object tells you where you are, which helps with separators, first and last items, and numbering.

{% for product in collection.products %}
{{ forloop.index }}. {{ product.title }}Index starts at 1; index0 starts at 0
{% if forloop.last %}(last){% endif %}Also first, length and rindex
{% else %}
No products yetRuns when the array is empty

String filters

Filters run left to right, each one taking the result of the one before. Arguments follow a colon and are separated by commas.

{{ 'hello world' | capitalize }}→ Hello world
{{ 'Hello' | upcase }}→ HELLO (also downcase)
{{ 'shop' | append: '.com' }}→ shop.com (also prepend)
{{ 'a-b-c' | replace: '-', ' ' }}→ a b c (also replace_first, remove, remove_first)
{{ ' hi ' | strip }}→ hi (also lstrip and rstrip)
{{ 'A long title' | truncate: 9 }}→ A long... (the ... counts toward the 9)
{{ 'One two three' | truncatewords: 2 }}→ One two...
{{ 'Summer Sale!' | handleize }}→ summer-sale
{{ '<p>Hi</p>' | strip_html }}→ Hi
{{ '<b>' | escape }}→ &lt;b&gt;
{{ 'Liquid' | slice: 0, 3 }}→ Liq
{{ 'Hello' | size }}→ 5
{{ product.description | newline_to_br }}Line breaks become br tags

Number & array filters

Math happens through filters rather than operators. Array filters can pull out, filter and sort collections of products, variants or cart items.

{{ 10 | plus: 5 }}→ 15 (also minus and times)
{{ 10 | divided_by: 4 }}→ 2: whole numbers when both are integers
{{ 10 | divided_by: 4.0 }}→ 2.5
{{ 10 | modulo: 3 }}→ 1
{{ 4.6 | round }} {{ 4.2 | ceil }} {{ 4.8 | floor }}→ 5 5 4
{{ 3 | at_least: 5 }}→ 5 (at_most sets an upper limit)
{{ product.tags | join: ', ' }}All items as one string
{{ cart.items | map: 'title' | join: ', ' }}One property from each item
{% assign in_stock = collection.products | where: 'available' %}Items where the property is true
{% assign shirts = collection.products | where: 'type', 'Shirt' %}Items where it equals a value
{% assign by_price = collection.products | sort: 'price' %}Also sort_natural and reverse
{{ product.tags | uniq | first }}Also last, compact and concat
{% assign units = cart.items | sum: 'quantity' %}Add up a property
{% assign acme = cart.items | find: 'vendor', 'Acme' %}The first matching item

Shopify filters

Shopify adds filters for money, images, assets, translations and dates. Prices are stored in cents, so always print them through a money filter.

{{ product.price | money }}→ $19.99, in the store's money format
{{ product.price | money_with_currency }}→ $19.99 USD
{{ product.featured_image | image_url: width: 600 | image_tag }}An img tag with srcset
{{ product.featured_image | image_url: width: 600 }}Just the image's CDN URL
{{ 'theme.css' | asset_url | stylesheet_tag }}Link a file from assets/
<script src="{{ 'theme.js' | asset_url }}" defer></script>
{{ 'products.product.add_to_cart' | t }}Translated text from locales/
{{ article.published_at | date: '%B %-d, %Y' }}→ October 1, 2026
{{ product.metafields.custom.subtitle | default: product.vendor }}Fallback for nil, false or empty
<script>const data = {{ product | json }};</script>Output as JSON for JavaScript
{{ product.title | link_to: product.url }}An a tag
{{ 'product-1' | placeholder_svg_tag }}Placeholder art when there's no image

Theme structure

A theme is a set of folders with fixed names. The layout wraps every page, JSON templates list which sections a page uses, and sections, blocks and snippets hold the reusable Liquid.

layout/theme.liquidThe page shell around every template
templates/product.jsonThe sections a page type uses, in order
sections/hero.liquidModules merchants add and configure
sections/header-group.jsonA section group, like the header area
blocks/slide.liquidTheme blocks, reusable inside sections
snippets/price.liquidReusable Liquid for {% render %}
assets/theme.cssCSS, JavaScript and images
config/settings_schema.jsonThe theme's global settings
locales/en.default.jsonTranslations for the t filter
<!doctype html>
<html lang="{{ request.locale.iso_code }}">
<head>
<title>{{ page_title }}</title>
{{ content_for_header }}Required: Shopify's scripts and analytics
</head>
<body>
{% sections 'header-group' %}Render a section group
<main>{{ content_for_layout }}</main>Required: the current template
</body>
</html>

Sections & schema

A section is a Liquid file with a schema: JSON that tells the theme editor which settings and blocks merchants can change. The Liquid reads those values through section.settings and block.settings.

<section class="hero">
<h2>{{ section.settings.heading }}</h2>A value the merchant set
{% for block in section.blocks %}
<p {{ block.shopify_attributes }}>{{ block.settings.text }}</p>The shopify_attributes output lets the theme editor select it
{% endfor %}
</section>
{% stylesheet %}CSS that ships with the section
.hero { padding: 2rem; }
{% endstylesheet %}
{% schema %}
{
"name": "Hero",
"settings": [
{ "type": "text", "id": "heading", "label": "Heading", "default": "Welcome" }
],
"blocks": [
{ "type": "text", "name": "Text", "settings": [{ "type": "text", "id": "text", "label": "Text" }] }
],
"presets": [{ "name": "Hero" }]Lets merchants add it in the theme editor
}
{% endschema %}

Theme blocks

Theme blocks live in their own files in blocks/ and can be reused across sections and nested inside each other. A section or block chooses where they render with content_for.

{% content_for 'blocks' %}Render the blocks the merchant added here
{% content_for 'block', type: 'price', id: 'price' %}A static block that's always there
{% schema %}
{ "name": "Product info", "blocks": [{ "type": "@theme" }, { "type": "@app" }] }Accept any theme block, and app blocks
{% endschema %}

Snippets & render

Snippets are reusable pieces rendered with render. A snippet can't see the variables around it, so pass in everything it needs; a doc tag at the top describes those inputs.

{% render 'price', product: product %}Pass variables as name: value
{% render 'card' for collection.products as item %}Once per item, with forloop available
{% render 'icon' with 'cart' as name %}Pass one value under a name
{% assign alt = image.alt | escape %}Filters can't go inside render, so assign first
{% render 'image', image: image, alt: alt %}
{% doc %}
Shows a product's price, with the compare-at price when there is one.
@param {product} product - The product to show
@param {boolean} [show_compare] - Optional; false if left out
@example
{% render 'price', product: product, show_compare: true %}
{% enddoc %}

Forms & pagination

The form tag outputs a form with the right action, method and hidden fields for Shopify features like the cart and customer accounts. paginate splits a long array into pages.

{% form 'product', product %}Adds the chosen variant to the cart
<select name="id">
{% for variant in product.variants %}
<option value="{{ variant.id }}">{{ variant.title }}</option>
{% endfor %}
</select>
<input type="number" name="quantity" value="1" min="1">
<button type="submit">{{ 'products.product.add_to_cart' | t }}</button>
{% endform %}

{% for product in collection.products %}…{% endfor %}

{% endpaginate %}

Strict parsing

Since January 2026, Shopify rejects Liquid it used to accept and silently misread. These are the most common patterns that now fail, with the fix for each.

{% assign show = a or b %}✗ And/or only work in if, elsif and unless
{% if a or b %}…{% endif %}✓
{% if a && b %}…{% endif %}✗ Use and, or
{% if a and (b or c) %}…{% endif %}✗ Parentheses aren't allowed
{% render 'card', title: t | escape %}✗ No filters inside render
{% assign title = t | escape %}✓ Assign first, then pass title
{% render 'card', product %}✗ Arguments need name: value
{{ [key] }}✗ Bare brackets are reserved for arrays
{{ self[key] }}✓ Look up a variable by name
{% include 'card' %}✗ Deprecated: use render
